# task-split-skill v2 改造文档

> 改造后的 task-split-skill 只负责拆解，不负责生成计划。

---

## 1. 改造原则

### 1.1 改造后的职责

**只负责拆解，不负责生成计划。**

| | 改造前 | 改造后 |
|--|--------|--------|
| **职责** | 生成计划 + 拆解任务 | 只拆解任务 |
| **计划生成** | 内置（重复问用户） | 交给 PLAN skill |
| **与 PLAN.md 关系** | 尝试解析 | 假设已由 PLAN skill 生成 |

### 1.2 改造后的工作流

```
用户说「拆解任务」/「开始执行」
    ↓
读取 docs/PLAN.md（如存在）
    ↓
LLM 复述理解，用户确认
    ↓
在 milestone 下拆 sub-task
    ↓
输出 milestone + subTask
    ↓
触发 target-skill（用户主动激活）
```

---

## 2. 触发条件（保持不变）

| 触发词 | 说明 |
|--------|------|
| `任务拆解` / `拆解任务` / `拆解成` | 核心触发 |
| `工作分解` / `WBS` | 专业术语 |
| `开始执行` / `执行计划` | 触发完整拆分 |

**不触发**：
- `制定计划` / `写 PLAN` → PLAN skill
- `评审计划` / `review PLAN` → plan-review-skill
- `追踪目标` → target-skill

---

## 3. 两种拆解模式

### 3.1 快速拆解

**触发**：用户说「拆解一下」（无 PLAN.md 或用户只想要扁平列表）

```markdown
## 澄清问题（必须先问）

1. 最终交付物是什么？
2. 成功标准是什么？
3. 限制条件有哪些？
4. MVP vs 完整版？

---

## 拆解结果

{扁平任务列表}
```

### 3.2 完整拆分（有 PLAN.md）

**触发**：用户说「开始执行」且 `docs/PLAN.md` 存在

```markdown
## Step 1：理解项目

读取 `docs/PLAN.md` 后复述：

> 我理解你的项目：
> - 目标：{目标描述}
> - 里程碑：M1({标题}), M2({标题})
> - 交付物：{交付物列表}
>
> 请确认是否正确。

---

## Step 2：拆解 milestone

在每个 milestone 下拆 sub-task：

### M1：{标题}

| ID | sub-task | 验收标准 | 优先级 |
|----|---------|---------|--------|
| M1-1 | {任务} | {标准} | P0 |
| M1-2 | {任务} | {标准} | P1 |

### M2：{标题}

...

---

## Step 3：触发追踪

**建议**：使用 target-skill 追踪执行。
```

---

## 4. 读取 PLAN.md 的 SOP

### 4.1 判断规则

```
拆解前检查 docs/PLAN.md 是否存在：
├── 存在 → 进入「完整拆分」模式
└── 不存在 → 进入「快速拆解」模式
```

### 4.2 读取后向用户确认

```markdown
## 我对 PLAN.md 的理解

**目标**：{LLM 理解的目标}
**里程碑**：
- M1：{标题} — 验收标准：{标准}
- M2：{标题} — 验收标准：{标准}
**交付物**：{交付物列表}

请确认以上理解是否正确，如有出入请告诉我。
```

### 4.3 用户纠正时的处理

```
如果用户纠正：
→ 接受纠正，更新理解
→ 继续拆解时按纠正后的内容

不质疑用户，不坚持自己的理解。
```

## 5. 输出格式（对标 .target-state.json）

### 5.1 完整拆分输出

```markdown
## 拆解结果

**项目**：{目标}
**模式**：完整拆分（基于 PLAN.md）

### Milestone + Sub-task

**M1：{标题}**
| ID | sub-task | 验收标准 | 优先级 | 状态 |
|----|---------|---------|--------|------|
| M1-1 | {任务} | {标准} | P0 | pending |
| M1-2 | {任务} | {标准} | P1 | pending |

**M2：{标题}**
| ID | sub-task | 验收标准 | 优先级 | 状态 |
|----|---------|---------|--------|------|
| M2-1 | {任务} | {标准} | P0 | pending |
| M2-2 | {任务} | {标准} | P1 | pending |

---

### 下一步

1. **开始执行** — 使用 target-skill 追踪
2. **修改拆解** — 告诉我需要调整哪些任务
3. **添加任务** — 告诉我需要在哪个 milestone 下添加
```

### 5.2 快速拆解输出

```markdown
## 拆解结果

**项目**：{目标}
**模式**：快速拆解

### 任务列表

| ID | 任务 | 验收标准 | 优先级 | 依赖 |
|----|------|---------|--------|------|
| 1 | {任务} | {标准} | P0 | — |
| 2 | {任务} | {标准} | P1 | #1 |
| 3 | {任务} | {标准} | P1 | #1 |

---

### 下一步

1. **开始执行** — 按顺序执行任务
2. **制定计划** — 如果需要更规范的流程，可以先制定 PLAN
3. **修改拆解** — 告诉我需要调整哪些任务
```

## 6. 关键改动说明

### 6.1 删除的内容

| 删除内容 | 原因 |
|---------|------|
| Step 1 的 4 个澄清问题（快速拆解模式下保留） | 完整拆分模式直接读 PLAN.md |
| 生成标准 PLAN.md 的能力 | 交给 PLAN skill |
| 尝试解析 PLAN.md 表格 | 改为复述 + 确认 |

### 6.2 新增的内容

| 新增内容 | 说明 |
|---------|------|
| 读取 PLAN.md 并复述确认 | 替代解析，保证可靠性 |
| 完整拆分模式 | 在 milestone 下拆 sub-task |
| 两种模式自动切换 | 根据是否有 PLAN.md 决定 |

### 6.3 保留的内容

| 保留内容 | 说明 |
|---------|------|
| 快速拆解模式 | 无 PLAN.md 时的 fallback |
| 验收标准强制 | 每个 sub-task 必须有验收标准 |
| 依赖建模 | sub-task 间的依赖关系 |
| P0/P1/P2 优先级 | 继承自 milestone 顺序 |

## 7. 与其他 Skill 的关系

### 7.1 与 PLAN skill 的关系

```
PLAN skill 生成 docs/PLAN.md
          ↓
task-split-skill 读取 docs/PLAN.md
          ↓
拆解任务
```

### 7.2 与 plan-review-skill 的关系

```
plan-review-skill 评审 PLAN.md
          ↓
评审通过后
          ↓
task-split-skill 拆解任务
```

### 7.3 与 target-skill 的关系

```
task-split-skill 拆解完成
          ↓
用户说「开始执行」
          ↓
target-skill 追踪 milestone + sub-task
```
