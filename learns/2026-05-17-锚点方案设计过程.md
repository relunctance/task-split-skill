# 锚点方案设计过程

> 日期：2026-05-17
> 项目：四 Skill 联动 + 锚点支持

---

## 问题发现

expert-teams 的 `task/PLAN.md` 共 3716 行，包含 M1~M5。

用户痛点：
- 想评审 M1-3，但 skill 只能评审整个文件
- 想拆解 M2，但 skill 只能拆解整个文件

---

## 方案讨论

### 方案 1：文件拆分
- 按 milestone 拆成 PLAN-M1.md、PLAN-M2.md
- 缺点：单文件被破坏，跨文件引用复杂

### 方案 2：锚点定位（最终选择）
- 保持单一文件，通过锚点（M1、M1-3）定位局部内容
- 优点：单文件不变，天然隔离

---

## 关键决策

### 决策 1：评审结果输出「修改建议」而非直接修改

理由：用户需要确认后才生效，避免 skill 擅自改文件。

### 决策 2：依赖检查规则先驳回再评审

场景：用户要评审 M2，但 M1 还没验收。

| M1 状态 | 行为 |
|---------|------|
| pending / rejected | 🔴 直接驳回 |
| approved | ✅ 允许评审，标注风险 |
| 未知 | ⚠️ 询问用户 |

### 决策 3：代码 0 行

全部用 SOP + LLM，Skill 是纯文档驱动。

## 踩坑记录

### 坑 1：M1 锚点识别错误

**问题**：最初验证时，用 L280 去读 M1，但 L280 是表格头，L281 才是 M1 数据行。

**解决**：milestones 表格格式：
```
| **M1** | 核心框架可运行 | demo3 全流程跑通 | ... |
```

第一列是里程碑 ID，需要精确识别数据行。

### 坑 2：依赖检查缺失

**问题**：没有定义「M1 未验收时能否评审 M2」。

**解决**：新增「依赖检查规则」章节，明确三种情况的处理方式。
